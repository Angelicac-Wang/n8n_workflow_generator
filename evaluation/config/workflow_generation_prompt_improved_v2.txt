## ⚠️ CRITICAL: Common Mistakes to Avoid

Based on analysis of 100+ workflow generation patterns, LLMs frequently make these mistakes:

### 1. Generating TOO FEW Nodes (Most Common Issue)
- **Problem**: LLMs tend to oversimplify workflows, generating ~80% fewer nodes than needed
- **Solution**: Real workflows need intermediate processing steps. Don't skip:
  - Data transformation nodes (Set, Code) between API calls
  - Error handling branches (IF, Switch nodes)
  - Data validation and formatting steps
  - Response handling nodes (respondToWebhook, httpResponse)

### 2. Missing Data Transformation Nodes
- **n8n-nodes-base.code**: For complex data processing, JavaScript logic (missing 50 times in analysis)
- **n8n-nodes-base.set**: For simple data mapping, variable setting (missing 20 times)
- When to use each:
  - Use **Set** for: Simple field mapping, renaming fields, adding static values
  - Use **Code** for: Complex calculations, loops, conditional logic, data restructuring

### 3. Forgetting AI Agent Workflows
When the request involves AI assistants, chatbots, or intelligent automation:
- **@n8n/n8n-nodes-langchain.agent**: Main AI agent orchestrator (missing 26 times)
- **@n8n/n8n-nodes-langchain.lmChatOpenAi**: For OpenAI GPT models in LangChain
- **@n8n/n8n-nodes-langchain.chatTrigger**: For chat-based workflows
- **@n8n/n8n-nodes-langchain.memoryBufferWindow**: For conversation history
- DO NOT use "n8n-nodes-base.openAi" for LangChain workflows - use LangChain-specific nodes

### 4. Node Type Confusion
Common mistakes:
- ❌ Using "n8n-nodes-base.openAi" instead of "@n8n/n8n-nodes-langchain.lmChatOpenAi" for AI agents
- ❌ Using "n8n-nodes-base.function" (doesn't exist) instead of "n8n-nodes-base.code"
- ❌ Using "n8n-nodes-base.schedule" instead of "n8n-nodes-base.scheduleTrigger"
- ❌ Using "n8n-nodes-base.webhook" instead of "n8n-nodes-base.webhookTrigger" for some cases

### 5. Missing Error Handling
Add error handling for:
- API failures (IF node to check response status)
- Data validation (Switch node for different data types)
- Fallback actions (alternative branches)

### 6. Insufficient Connections
- Average workflows need ~11 connections, not just 5-6
- Include all data paths: success, error, and alternative branches
- Don't leave nodes orphaned

## 📋 Pre-Generation Checklist

Before generating the workflow JSON, verify your plan includes ALL of these:

### Workflow Structure
- [ ] **Trigger node**: How does the workflow start? (webhook, schedule, manual, etc.)
- [ ] **All processing steps**: Don't skip intermediate data transformation steps
- [ ] **Output/action nodes**: What happens with the final result?

### Data Flow
- [ ] **Data extraction**: Set/Code nodes to extract and structure data from trigger
- [ ] **Data transformation**: Set/Code nodes between API calls to format data
- [ ] **Data validation**: IF/Switch nodes to check data quality

### Error Handling
- [ ] **API error handling**: What if external API fails?
- [ ] **Data validation**: What if required fields are missing?
- [ ] **Fallback actions**: Alternative paths for error cases

### AI Workflows (if applicable)
- [ ] **LangChain nodes**: Use @n8n/n8n-nodes-langchain.* nodes, not base nodes
- [ ] **Agent node**: Include agent orchestrator for AI workflows
- [ ] **Memory**: Add memory nodes for conversational workflows
- [ ] **Tools**: Include tool nodes for agent actions

### Connections
- [ ] **All nodes connected**: No orphaned nodes
- [ ] **Branch handling**: Multiple outputs from IF/Switch nodes
- [ ] **Parallel processing**: Use merge nodes when needed

## 🔧 Commonly Needed Node Types

### Data Processing (Use These Often!)
- **n8n-nodes-base.set**: Simple data mapping, field renaming, variable setting
- **n8n-nodes-base.code**: Complex JavaScript logic, calculations, data restructuring
- **n8n-nodes-base.merge**: Combine data from multiple branches

### Control Flow
- **n8n-nodes-base.if**: Binary decision (true/false)
- **n8n-nodes-base.switch**: Multiple conditions routing
- **n8n-nodes-base.splitInBatches**: Process items in batches/loops

### AI & LangChain Nodes (For AI Workflows)
- **@n8n/n8n-nodes-langchain.agent**: AI agent orchestrator
- **@n8n/n8n-nodes-langchain.lmChatOpenAi**: OpenAI GPT models
- **@n8n/n8n-nodes-langchain.chatTrigger**: Chat interface trigger
- **@n8n/n8n-nodes-langchain.memoryBufferWindow**: Conversation memory
- **@n8n/n8n-nodes-langchain.toolCode**: Custom tools for agents

### Response Handling
- **n8n-nodes-base.respondToWebhook**: Send response back to webhook caller
- **n8n-nodes-base.httpResponse**: Send HTTP response (for webhooks)
